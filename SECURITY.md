# Безопасность Private Music

## Сообщить об уязвимости

Отправьте приватный отчёт через
[Security → Report a vulnerability](https://github.com/decoder-dev/PrivateMusicDesktop/security/advisories/new).
Не публикуйте действующие токены, cookie, пароли, ключи подписи или данные аккаунта в issues.

Опишите проблему, затронутую версию, условия воспроизведения и возможные последствия.
По возможности приложите минимальный пример без настоящих учётных данных.
Поддерживается последний стабильный выпуск; исправления разрабатываются в `main`.

## Автоматические проверки

- GitHub secret scanning и push protection ищут известные секреты и предотвращают их попадание в Git.
- Dependabot отслеживает зависимости Cargo, npm, Gradle и GitHub Actions и предлагает обновления PR-ами.
  Обновления не сливаются автоматически.
- Gradle Dependency Submission передаёт зависимости обоих Android-плагинов в Dependency Graph.
- Dependency Review проверяет изменения зависимостей в PR. При уязвимости уровня high или critical
  проверка завершается ошибкой; это не заменяет правила защиты ветки.
- CodeQL с расширенным набором запросов анализирует Rust, C/C++, JavaScript/TypeScript, Python,
  GitHub Actions и скомпилированный код Kotlin двух Android-плагинов на push/PR и еженедельно.
  Вспомогательные Swift-oracle для сравнения с iPhone не входят в этот анализ; они не поставляются
  внутри приложения. Shell, PowerShell и CSS не поддерживаются этим набором анализаторов.

Проверки запускаются без ключей подписи. Задания получают только необходимые разрешения,
а внешние Actions закреплены по SHA коммита. Платные функции GitHub не подключаются автоматически.
Наличие проверок не означает отсутствия уязвимостей.

## Ключи выпуска

Ключи Android и обновлений ПК хранятся в GitHub Actions Secrets и в резервной копии вне Git.
Открытый ключ проверки обновлений ПК находится в конфигурации приложения.
Проверка цифровой подписи пакета обновления отличается от сертификата издателя Windows
и нотариализации Apple. Подробности: [обновления](docs/updates.md).
