# Обновления Private Music

ПК и Android используют один GitHub Release, но разные механизмы установки.
Проверка запускается пользователем в Настройках. После обнаружения новой версии
загрузка и установка следуют автоматически; до установки загрузку можно отменить.

## Компьютер

Tauri Updater 2 проверяет `latest.json` из последнего выпуска, выбирает пакет для
ОС, архитектуры и способа установки, проверяет его подпись и устанавливает обновление.
Windows использует NSIS; macOS — архив приложения; Linux — AppImage или DEB.
Установка системного пакета может запросить права через системный диалог.
После успешной установки приложение перезапускается. Повторная проверка подписи
выполняется непосредственно перед установкой.

`TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` хранятся в GitHub
Actions Secrets. В приложение включён только открытый ключ. Он не заменяет подпись
издателя Windows или нотариализацию macOS. Закрытый ключ нельзя менять между выпусками
без заранее подготовленного перехода.

## Android

Rust получает последний стабильный релиз через GitHub API и выбирает только
`PrivateMusic_<версия>_android-arm64.apk`, без `unsigned`. Скачивание ограничено по размеру,
частичный файл не считается готовым. Проверяются размер и SHA-256 из `SHA256SUMS.txt`;
хеш повторно вычисляется перед передачей установщику.

Kotlin допускает APK только из приватной папки обновлений, с именем пакета текущего
приложения, более высоким versionCode и тем же сертификатом подписи. Android дополнительно
проверяет APK при установке. Через FileProvider установщик получает временное право чтения.
Если установка из Private Music ещё не разрешена, открывается соответствующий экран
настроек; после выдачи разрешения нажмите «Установить обновление» ещё раз.

Ключ APK хранится в `ANDROID_KEYSTORE_BASE64`; дополнительные секреты:
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
Установка подтверждается пользователем в интерфейсе Android.

## Выпуск

1. Обновите версии в `Cargo.toml` и `src-tauri/tauri.conf.json` и lock-файл Cargo.
2. Отправьте тег `v<версия>` либо запустите Release вручную с новым тегом.
3. Workflow собирает все платформы, подписывает пакеты обновления, создаёт `latest.json`
   и контрольные суммы. Выпуск публикуется только после успеха всех сборок.

Первую версию с новым механизмом следует установить обычным установщиком. Более ранние
установленные версии могут скачивать установщики прежним способом.

Резервные копии обоих закрытых ключей и паролей храните вне Git и отдельно от компьютера.
GitHub Secrets не позволяют скачать исходные значения для восстановления.
